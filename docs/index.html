Guardrails

自动化再往前一步，
边界也画清楚。

全自动不等于放任：该拦的拦住，该叫人的叫人，每一步都留证据。

  • 自动放行 fail-closed：项目没配白名单前缀就绝不自动合入，收尾改为通知项目负责人人工合并。
  • 冲突必须通知人：无法 fast-forward 的 MR 不重试、不强推，直接 @ 负责人。
  • 评审结论可追溯：每条 AI 初审结论落库并回帖 MR，谁在什么时候放的行有据可查。
  • 过程全量留痕：runner 回传的思考 / 工具调用 / 结果全量落库，任务详情页可回放。

Architecture

一个仓库，两个入口。

api 是控制面，runner 是可多节点的执行面；web 是唯一界面。GitLab 与 octo 都是外部系统，靠 webhook 与 bot API 对接。

控制面 / 执行面分离

api 负责状态机、webhook、定时任务与数据落库；runner 每个节点独立驱动 claude，领任务、跑 worktree、回传事件。加容量就是加 runner 节点，api 不动。

octo 群 ← 播报/派单 ← vega-api ← webhook ← GitLab 13.12
                        ↑  ↓ 长轮询
                    vega-runner（可多节点，每节点驱动 claude -p）
                        ↑ SSE 流式
                     vega-web（React 18 + antd 5）
Quickstart

compose 起服务，接上 GitLab 就能跑。

依赖 Docker + Docker Compose v2；默认外接 PostgreSQL，也可以加 profile 起内置 PG。runner 节点另需 claude CLI。

部署细节（建库、runner 注册、webhook 接线、密钥不可更换的原因、备份恢复）见 deploy/README.md。 

# 1. 配置
git clone https://github.com/whalezhao/vega.git
cd vega
cp .env.example .env
# 至少改 VEGA_SECRET_KEY 和数据库口令

# 2. 启动
docker compose up -d --build api web

# 3. 登录后台，在「集成」页填 GitLab 地址与 token
#    webhook 指向 <VEGA_API_URL>/webhooks/gitlab
